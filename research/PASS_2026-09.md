## 2 · Trade voice — likes and dislikes, as far as this seat could read them
Likes that recur: **fast to first number**, **easy**, **value**, **support that answers**, **my own formulas**.
Dislikes that recur: **price creep** (seats, reports, add-ons), **device and login lock**, **mobile that is a worse copy of desktop**,
**rigid estimate formats**, **exports that lose the math**, **tools that lock up**, **aerial sketch tools that fail under tree cover**.
INF: every dislike is a trust or ownership complaint before it is a feature complaint. VES's stated position (file you own,
zero egress, no account) answers the class; the pass should verify the product *says* it where a buyer looks (landing, README,
first bid) and *behaves* like it (no lockup on a 40k-segment sheet — OBS: 1.2 s to raster at 4× throttle).

## 3 · Game-UI craft — the principles that transfer, checked against the bytes
| principle | source | VES today (OBS) | row |
|---|---|---|---|
| Minimum viable HUD; contextual > always-on; on-demand for the rest | SRC [StraySpark](https://www.strayspark.studio/blog/game-ui-ux-design-principles) | ≤8%-at-rest chrome rule (F18.22); recap summoned, not docked | holds |
| Information priority tiers: critical large/animated, informational small/subtle | same | sell strip = critical; toast = informational; armed state = important (pill) | holds; verify the tiers survive on the phone lens |
| Input-to-visual response under 16 ms; transitions under 200 ms; never block input during animation | same | rAF-coalesced rail rebuild (§feel-2); no measured number for the trace path | **G1** measure it |
| "Juice" is communication: every confirmed input gets a perceivable response | SRC [Medium, Juicy UI](https://medium.com/@mezoistvan/juicy-ui-why-the-smallest-interactions-make-the-biggest-difference-5cb5a5ffc752) | `flashDriving` on the BOM; sell HUD repaints | **G2** a money change is perceivable within 200 ms on every lens |
| Don't make the player leave context to check status (glanceable, not navigational) | SRC [Factorio FFF-423](https://factorio.com/blog/post/fff-423) | recap panel over the sheet; Estimate lens is a context switch | **G6** per-condition money on hover/long-press of a card, no lens switch |
| Learnable complexity: introduce one concept at a time; interactive tutorial | SRC [Game Accessibility Guidelines](https://gameaccessibilityguidelines.com/full-list/) (basic: "include interactive tutorials") | landing page three-step text; no guided first bid | **G3** "first bid" guided run on the synthetic demo |
| Remappable controls; single-key actions; no timing-critical input | GAG basic/intermediate | 1–9 arming, ⌖, backtick palette, Esc grammar; no remap; no timing-critical input (good) | **G4** remap surface for the arming keys |
| Color is never the only channel | GAG basic | confidence dots carry glyph + tag; legend swatches now print (F18.59) | holds |
| Readable default font; allow UI/font scaling | GAG basic/advanced | fixed 12.5–13 px chrome; no scale option | **G5** UI scale setting (persisted like theme) |
| Remind of controls in play; contextual help | GAG intermediate | `#cmdhint`, hotkeys modal, tooltips | holds; verify on phone lens |
| Settings remembered | GAG basic | theme persisted; grid ft, fills, rail state partly | **G7** every rest-state preference persisted |
| Touch targets ≥ 44 px | StraySpark "common mistakes" | 40 px on coarse pointers (F18.59) | raise to 44 in the Field lens |

## 4 · The seat's own method — Claude Code guidance, applied to this repo
From the current docs ([best practices](https://code.claude.com/docs/en/best-practices), [/goal](https://code.claude.com/docs/en/goal),
[subagents](https://code.claude.com/docs/en/sub-agents), [workflows](https://code.claude.com/docs/en/workflows),
[scheduled tasks](https://code.claude.com/docs/en/scheduled-tasks)):
- **Verification gates the stop.** Already true here: the Stop hook runs the verifier. Add the batch gate to it? No — keep the
  hook deterministic and cheap (verifier), and run G0 + probe-v as the `/goal` condition of a batch: `probe-v prints 17/17 and
  g0 prints G0 GREEN and the verifier prints RESULT PASS`. The evaluator is a fresh model, so the seat doing the work is not the
  one grading it — the same rail NOTES.md carries as "no agent self-grades".
- **Subagents for research and persona passes**, never for the money edit itself. Personas run read-only (`tools: Read, Grep,
  Glob, Bash`), in their own context, and return findings files; the seat triages against the rubric. Definitions in
  `.claude/agents/` (added with this pass).
- **Workflows for the fan-out + adversarial verify** shape: one agent per persona lane, then one verifier per finding that tries
  to refute it (the docs' "audit many, verify each finding"). Run on opt-in only (`ultracode` or "use a workflow"); the shape
  is written in §5.4 so any seat can ask for it.
- **CLAUDE.md stays short** and gains one compaction line so the identity block, gate outputs and open rulings survive
  summarization. Domain detail stays in NOTES/LEDGER/skills, not in CLAUDE.md.
- **`/loop`** tends the branch between batches (CI, review comments, merge state); `.claude/loop.md` (added) says what
  "tend" means here. **Cloud Routines** for anything that must run with no session open.
- **Worktree isolation** for experimental batches (`isolation: worktree`), so a failed experiment never touches the checkout.
- **Auto mode's classifier** blocked a remote tag delete this session; that is the right failure — outward, destructive acts
  stay with Patrick.

## 5 · The pass — charter
### 5.1 Personas (one subagent each, read-only, synthetic fixtures only)
- **P-MARKET** — reads §1's sources and the bytes; files rows where VES claims less than it does or does less than the bar.
- **P-TRADE** — the buyer who has been burned: prices, seats, devices, exports, lockups; judges landing, README, first bid, exports.
- **P-GAME** — the game-UI reviewer: HUD tiers, feedback timing, context switches, learnability, remap, scale, persistence; judges
  every lens on desktop and the phone profile with real pointer/touch events.
- **P-SEAT** — the method reviewer: reads CLAUDE.md, NOTES.md, LEDGER.md, the workflow and hooks against the current docs; files
  where the rails contradict the docs or each other.
### 5.2 Rules (carried lessons, unchanged)
Personas report what they SAW, never a mechanism (lesson 4). A finding names the surface, the state, the expected outcome, and the
evidence path. Triage by the NOTES.md rubric: (a) money-honesty → fix this wave; (b) backed by a bar row → severity per the bar;
(c) taste → CANDIDATE; (d) contradicts a ruling → record the tension. A finding closes only by the filing persona's re-run.
### 5.3 Bar rows v3 (artifact outcomes; new rows only)
| row | outcome on the artifact | evidence |
|---|---|---|
| M1 revision delta | opening a revised PDF over a matching takeoff lists which measurements sit on sheets that changed | probe: two synthetic PDFs, one line moved |
| M2 formulas in Excel | the Estimate XLSX carries live formulas for extensions and ladder, not values only | open in LibreOffice headless; cells are formulas |
| M3 bid alternates | one takeoff prints a base bid and a named alternate without cloning the file | rendered bid bytes |
| T1 the absence stated | landing + README say: no seat fee, no report fee, no device limit, no login | text on both surfaces |
| T2 no lockup | a 40k-segment sheet rasters under 2 s at fit on a 4×-throttled profile; input never blocked > 200 ms | probe timing |
| G1 input latency | first paint of a trace point within 16 ms of the tap/click at fit zoom | probe: performance timeline |
| G2 money feedback | a sell change is perceivable within 200 ms on Plan, Estimate, Field lenses | probe: mutation timestamp |
| G3 first bid | a guided run on the synthetic demo reaches a printed bid in under 12 gestures with no dead ends | scripted persona run |
| G4 remap | arming keys and the palette key are remappable and persisted | settings round-trip |
| G5 UI scale | a UI scale setting (0.9–1.5×) persists and every lens stays hittable | probe at 1.5× |
| G6 glanceable money | hover/long-press on a condition card shows its priced lines and sell share without leaving the sheet | probe: no lens change |
| G7 rest state persists | rail, drawer pin, fills, grid ft, theme, scale all restore on reload | round-trip |
| S1 goal-gated batches | every batch's PR shows the `/goal` condition met (probe-v, G0, verifier) in its record | transcript + CI |
| S2 personas isolated | persona findings are produced by read-only subagents with no write tools | agent definitions |
| S3 compaction rule | CLAUDE.md carries the compaction line; a compacted session still knows the identity block and open rulings | observed after a compaction |
### 5.4 Runnable shape (workflow, opt-in)
```
phase Review:  P-MARKET · P-TRADE · P-GAME · P-SEAT in parallel (read-only agents, schema: findings[])
phase Verify:  one agent per finding tries to refute it against the bytes and a probe (schema: {isReal, evidence})
phase Triage:  one agent ranks confirmed findings by the rubric and writes evidence/PASS_2026-09/findings.md
```
Any seat starts it with "use a workflow to run the PASS_2026-09 personas and adversarially verify each finding". Findings go
under `evidence/` in the repo (synthetic only), triage rows into `LEDGER.md`, and each landed fix is a batch with its own
red-first probe.
